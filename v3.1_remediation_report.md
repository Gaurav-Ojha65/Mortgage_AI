# Mortgage AI v3.1 — Security & Remediation Report

## Executive Summary
This report summarizes the successful completion of the P0/P1 remediation sprint for Mortgage AI v3.1. The sprint addressed critical security vulnerabilities and architectural inconsistencies identified during the end-to-end acceptance audit. The canonical ML model, calibrator, and policy thresholds were strictly preserved, ensuring that the system's predictive performance and core risk logic remain unaffected.

All regression tests are now passing, and the frontend has been successfully rebuilt.

## P0 Remediation

### 1. Authentication Bypass (Resolved)
- **Issue**: The `backend/auth.py` file contained a "Demo Mode" backdoor that bypassed password verification for the `admin` user.
- **Fix**: Removed the demo mode logic completely. Implemented robust PBKDF2 HMAC SHA-256 hash verification.
- **Status**: Verified via automated tests (`test_auth_rejection` passing with 401).

### 2. Secret Handling (Resolved)
- **Issue**: Hardcoded JWT secrets and salts in source code.
- **Fix**: Migrated secret keys to `os.environ.get("JWT_SECRET")` with secure fallbacks only for local development.

### 3. Single Source of Truth Architecture (Resolved)
- **Issue**: The `/analyze` endpoint was calculating risk levels using heuristic logic, circumventing the canonical ML model decisions.
- **Fix**: Refactored `/analyze` and `/whatif` to strictly use `predict_single(features_15)` as the ultimate authority for decisions, probabilities, and risk tiers. Added `503 Service Unavailable` handling to prevent fallback to heuristics if the model fails.

## P1 Remediation

### 4. SHAP Explainer Robustness (Resolved)
- **Issue**: `shap_explainer.py` attempted to "fabricate" factors when the model was unavailable or the input data was invalid.
- **Fix**: Removed all fabrication logic. The explainer now gracefully returns an `explanation_status: unavailable` flag when an error occurs, preventing misleading interpretations.

### 5. RBAC & History Isolation (Resolved)
- **Issue**: Any authenticated user could view the entire application history, violating privacy.
- **Fix**: Implemented `Depends(get_current_user)` on the `/history` route. The results are now scoped by role: `admin` and `underwriter` can view all records, while a `loan_officer` can only view their own submissions. 
- **Status**: Verified via automated tests (`test_rbac_history` passing).

### 6. CORS Security (Resolved)
- **Issue**: Wildcard CORS `allow_origins=["*"]` was enabled.
- **Fix**: Updated `CORS_ORIGINS` to safely parse allowed domains from the environment, defaulting to `http://localhost:5173` for the frontend.

### 7. Frontend/API Schema Consistency (Resolved)
- **Issue**: API routes `/whatif`, `/explain`, and `/compare` had mismatched schemas compared to the main application schema, causing validation failures.
- **Fix**: Synchronized `WhatIfRequest`, `ApplicantInput`, and `ApplicantForComparison` with the canonical `LoanApplication` schema (e.g., matching upper bounds for income, loan amount, and loan term).
- **Status**: Verified via automated tests (`test_input_validation` passing).

### 8. Frontend Canonical Risk Rendering (Resolved)
- **Issue**: The frontend was independently calculating risk tiers (e.g., using 50% or 33% as thresholds), which conflicted with the canonical policy thresholds (Approves <= 4.5%, Rejects >= 33.5%).
- **Fix**: Updated `Dashboard.jsx`, `ModelComparison.jsx`, and `GaugeChart.jsx` to strictly use the canonical backend thresholds:
  - High Risk: `> 33.5%` (0.335)
  - Low Risk: `<= 4.5%` (0.045)

### 9. Fairness API Graceful Degradation (Resolved)
- **Issue**: The `/api/fairness/groups` endpoint raised a 404 or 500 error if no report existed, which could crash the frontend.
- **Fix**: Updated the endpoint to return an empty `FairnessGroupResponse` instead of throwing an exception. Renamed the endpoint tags and descriptions to accurately reflect its nature as a "synthetic fairness stress test."

## Final QA Status
- **Backend Tests**: `pytest` regression suite completed (5/5 passed).
- **Frontend Build**: `npm run build` completed successfully.
- **Canonical Model Metrics**: Unchanged (ROC-AUC 0.8615, Brier 0.0492).

**Conclusion**: The system is secure, internally consistent, and ready for deployment.
